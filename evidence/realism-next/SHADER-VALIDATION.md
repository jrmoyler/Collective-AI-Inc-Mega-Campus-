# Native shader and framebuffer validation — September 17, 2026

`node scripts/check-campus-shaders.mjs --output /tmp/campus-shader-evidence`

All **17 actual shader programs** compile and link under **OpenGL ES 3.2 Mesa 25.2.8**, using **llvmpipe LLVM 20.1.2**. Both stages compile individually and their interfaces link successfully:

- Water with daylight environment mapping; water with environment mapping and directional shadows.
- Instanced botanical foliage; instanced pink foliage with directional shadows; non-instanced foliage.
- Cyan and gold kinetic roads; atmospheric Sky.
- UnrealBloomPass luminosity high-pass, all five blur mip programs, bloom composite, additive copy.
- OutputPass with the application's ACES filmic tone mapping and sRGB output defines.

The checker creates the actual landscape material and calls its `onBeforeCompile` hook. It does the same for the actual botanical factories. It constructs UnrealBloomPass and executes OutputPass's real define-selection branch with runtime renderer settings. Three.js revision 186's own `WebGLProgram` generates renderer prefixes, include expansion, light-count substitution, and GLSL ES conversion. A recording context captures the final, unchanged strings; a separate Python helper sends them to a real native EGL compiler. No replacement shaders are substituted. Ordinary programs use GLSL ES 3.00; the raw OutputPass preserves Three's GLSL ES 1.00 source path.

A negative control changes only the fragment stage's water varying from `vec3` to `vec4`. Both stages still compile, but native linking correctly rejects the interface mismatch. This verifies that native compilation and linking actually execute.

## Half-float MSAA framebuffer evidence

The same native helper queries format-specific sample counts and allocates 128 × 128 test targets with these results:

| Native check | Result |
|---|---|
| Global maximum samples | 4 |
| RGBA16F renderbuffer supported samples | 4 |
| DEPTH_COMPONENT24 supported samples | 4 |
| RGBA16F texture + depth24 framebuffer | Complete (`0x8cd5`) |
| 4× RGBA16F + depth24 multisample framebuffer | Complete (`0x8cd5`) |
| Clear → multisample resolve → float readback | Exactly `[0.25, 0.5, 0.75, 1]` |
| GL errors during allocation and resolve | None |
| Missing-attachment negative framebuffer | Incomplete (`0x8cd7`), without exception |

The negative framebuffer demonstrates why JavaScript `try/catch` alone cannot detect an incomplete target. Global `MAX_SAMPLES` also does not establish sample support for every attachment format. Runtime allocation should choose the intersection of RGBA16F/depth24 supported sample counts, test actual framebuffer completeness, retry without MSAA, and fall back to base rendering if the targets remain incomplete. Checks must run again after target resizing and context restoration.

`shader-native-report.json` records native compile/link logs, per-program SHA-256 hashes, and framebuffer results. Expanded shader files are generated by the command above, avoiding redundant checked-in copies of Three's shader library.

## Limits

This is **offline native compiler and small framebuffer evidence**, not browser WebGL validation. It does not render the campus, validate image appearance, exercise WebGL-specific validator differences, test viewport-size allocation limits, measure performance, or establish Galaxy A15 compatibility. These remain separate browser/device gates. The compiler is software Mesa, not the user's mobile GPU.

Prerequisites: installed project dependencies, Python 3, and native `libEGL`/Mesa with a surfaceless OpenGL ES 3 context. The helper explicitly defaults to software rendering. No browser is launched.
