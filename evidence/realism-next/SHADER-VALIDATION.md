# Native shader compilation — September 17, 2026

`node scripts/check-campus-shaders.mjs --output /tmp/campus-shader-evidence`

All eight GLSL ES 3.00 programs compile and link under **OpenGL ES 3.2 Mesa 25.2.8**, using **llvmpipe LLVM 20.1.2**. Both stages compile individually and their interfaces link successfully:

- Water with daylight environment mapping.
- Water with environment mapping and directional shadows.
- Instanced botanical foliage.
- Instanced pink foliage with directional shadows.
- Non-instanced botanical foliage.
- Cyan and gold kinetic roads.
- Three.js atmospheric Sky.

The checker creates the actual landscape material and calls its `onBeforeCompile` hook. It does the same for the actual botanical material factories. Three.js revision 186's own `WebGLProgram` generates the renderer prefixes, include expansion, light-count substitution, and GLSL ES conversion. A recording context captures these final, unchanged strings; a separate Python helper sends them to a real native EGL compiler. No handwritten replacement shader is substituted.

A negative control changes only the fragment stage's water varying from `vec3` to `vec4`. Both stages still compile, but native linking correctly rejects the interface mismatch. This verifies that the validation gate is actually executing native compilation and linking.

`shader-native-report.json` records native compile/link logs and SHA-256 hashes of each final shader. Expanded shader files are generated by the command above, avoiding redundant checked-in copies of Three's shader library.

## Limits

This is **offline native compiler evidence**, not browser WebGL validation. It does not render a frame, validate image appearance, exercise WebGL-specific validator differences, measure performance, or establish Galaxy A15 compatibility. These remain separate browser/device gates. The compiler is software Mesa, not the user's mobile GPU.

Prerequisites: installed project dependencies, Python 3, and native `libEGL`/Mesa with a surfaceless OpenGL ES 3 context. The helper explicitly defaults to software rendering. No browser is launched.
